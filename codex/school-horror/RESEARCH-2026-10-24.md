# 画像だけで歩ける空間を作るための追加調査

調査日: 2026-10-24。今回は資料調査と記録のみ。ステージのコード・画像・依存パッケージは変更していない。

## 結論と、前回の説明の修正

候補はPOMと8方向スプライトだけではなかった。優先して比較したいのは、**部品に分けた画像面、深度付きスプライト、家具レイヤーを持つ室内表現**の3つ。

前回「椅子の方向画像の整合性が課題」と説明したが、それだけでは不十分だった。現在の stage.js は角度で一枚を選んで板を向ける方式で、撮影時の投影への補正、深度に基づく視点間の再投影、ピクセルごとの深度は持たない。素材を揃えるだけで製品水準のインポスターになるとは言えない。

また、現在の interior.js は一枚の教室写真を仮想の室内へ再投影する簡略版。壁・床・天井と家具を分ける方式も既に存在している。次はこの違いを比較する。

この文書の「今回への判断」は資料からの推論で、実機で採用を検証した結果ではない。

## 1. 増やす情報は何か

カラー画像だけには、輪郭の内側の形、手前と奥の距離、隠れた側面、動く光への反応が十分に入っていない。各方式は違う情報を足している。

|足す情報|主な手法|見た目への作用|
|---|---|---|
|面の向き|手描きNormal、複数の照明方向からの画像|光が動いたときに塊の明暗が動く|
|各画素の距離|Depth sprite、Relief、POM|視差、他の物との前後関係を付ける|
|隠れていた面や層|Billboard Clouds、複数深度、画像の積層|回り込み時の穴や欠けを減らす|
|別方向からの姿|投影補正付き多方向Impostor|側面・背面・上面への変化を作る|

画像ファイルに保存する方式でも、形に対応する補助画像を作る工程は必要になる。3Dモデルを制作元にする例と、手描きの補助画像で作る例は区別した。

## 2. 追加候補の比較

|方式|やること|今回の用途の候補|主な弱点と制作条件|
|---|---|---|---|
|部品ごとの固定カード / Billboard Cloudsの考え方|座面、背、脚などの画像面を別々の位置・向きに置く|近くで見る椅子、窓枠、掲示物|面の端が見える。部品の重なりと裏面が必要。元の論文は3Dモデルからの自動変換なので、手描き素材での組立は応用案|
|Sprite stacking / 断面画像の積層|高さ別の断面画像を重ねる|小物の比較実験|一人称で水平近くから見ると層間の隙間・段差が出る懸念。既存実装の作者自身も特定のライブラリを非推奨としている|
|Depth sprite / RGB-D reprojection|色に各画素の奥行きを添えて別視点へ投影|窓枠、近景の小物、正しい遮蔽|一方向の深度には裏面がない。深度境界で穴が開く。法線・影は別に考える必要がある|
|True Impostors / 多層Relief|板を入口として複数の深度層へ視線を飛ばす|椅子のような空隙のある物体の研究候補|一枚の高さ画像より複雑な素材が必要。画面を占める大きさと探索回数で負荷が増える|
|投影補正と深度補間を持つ多方向Impostor|複数方向の色・深度を使い、現在の視点へ再投影する|中距離の小物、遠景の樹木|近距離、細い部材、画像間で不一致のある形に弱い。単純な画像切替とは違う|
|部屋の面ごとのInterior Mapping + 家具の画像層|壁・床・天井を個別に引き、手前の家具を別層で遮蔽する|教室のドア越し、窓越し|家具の画像層自体は平面。入室可能な部屋全体の代用にはしない|
|手描きNormal / 照明方向別の補助画像|色とは別に塊の向きと光の反応を指定する|枠の丸み、椅子の座面、壁の大きい面|視差と外形は増えない。カラーの明暗をそのまま凹凸にすると汚れや描き込んだ影まで盛り上がる|
|LDI / MPI / 深度付き写真の穴埋め|奥行きの異なる層と、元画像で隠れていた部分を用意する|廊下奥、外景、限定された視差|一枚の写真を部屋全域の自由歩行へ広げる用途には、そのままでは不足。画像の見えていなかった部分の制作が必要|

## 3. 開発者自身の説明から得たもの

### S01: Fortnite — Ryan Brucks

2018年の記事で、投影の補正、近い3視点の合成、深度による視差補正を段階的に説明している。単純に最寄りの絵を板へ貼る方法には回転や切替の問題がある。記事の代表的な用途は中遠景で、近接用の万能手法とは扱わない。

[Octahedral Impostors](https://shaderbits.com/blog/octahedral-impostors)

今回への判断: stage.js の単純な角度切替を、完成したoctahedral impostorと呼ばない。細い脚のある近景の椅子は、別方式とも比較する。

### S02: Brigador / Brigador Killers — Stellar Jockeys

公式制作資料では、色のスプライトとz-depthを出力し、深度を描画に利用している。別の影の解説では、低い角度の光で段差が出る問題と、光源側からの深度を追加する案も説明している。見た目が2Dでも、影まで一枚のカラー画像で済ませてはいない。

[2021年9月・制作工程](https://stellarjockeys.com/wp-content/uploads/2021/10/September-2021-archive.pdf)、[2021年11月・影の問題](https://stellarjockeys.com/wp-content/uploads/2021/12/November-2021-archive.pdf)

今回への判断: 椅子の接地を黒いぼかし画像だけで済ませると限界がある。深度・遮蔽・影を分けて考える。ただし同作の制作元は3Dモデルで、カメラの条件も今回と異なる。

### S03: The Siege and the Sandfox — Keith Duke-Cox / Cardboard Sword

開発者インタビューでは、細かいNormalを増やした最初の試みはノイズになり、大きな形を彫るように手描きすると良くなったと説明している。また、カラーの値から形を推測する方法の不正確さにも触れている。

[Adding depth to 2D with hand-drawn normal maps](https://www.gamedeveloper.com/art/adding-depth-to-2d-with-hand-drawn-normal-maps-in-i-the-siege-and-the-sandfox-i-)

今回への判断: 壁の傷を強調するより、枠・座面などの大きい面の向きと光の連続性を先に作る。細部を強めれば立体的になる、とは考えない。

### S04: Smack Studio — ThirdPixel Interactive

公式説明には、部位別の2D画像を骨格へ結び、生成・修正できる深度画像とcompute shaderで回転後の像を描く方式がある。3Dモデルを作らずに画像から回転表現を作る実例として重要。公開されているのは概要で、自由な全周表示の品質をこちらで検証したわけではない。

[公式技術概要](https://smackstudio.com/press/)

今回への判断: 「形の情報を画像で制作する」という選択肢を残す。同製品の仕組みをそのまま導入できる公開ライブラリと混同しない。

### S05: Sprite Lamp — Finn Morgan / Snake Hill Games

異なる方向から照らしたように描く補助画像を入力し、Normal・Depth・AOなどを作る。手描きだけで補助情報を作る制作手法の例。プレビューが立体視点移動を扱わないという説明もあり、照明デモだけで自由視点に対応すると判断しない。

[開発者の説明](https://www.snakehillgames.com/spritelamp/)

今回への判断: 画像生成に完成した照明込みの一枚絵だけを求める工程を見直す候補。製品の購入・インストールはしていない。

### S06: Dead Cells — Thomas Vasseur / Motion Twin

開発者本人が、3Dで制作したアニメーションから各フレームのPNGとNormalを出力する制作工程を説明している。画像と補助画像を同じ工程で揃える利点を持つが、制作元まで2D限定の方法ではない。

[Using a 3D pipeline for 2D animation](https://www.gamedeveloper.com/production/art-design-deep-dive-using-a-3d-pipeline-for-2d-animation-in-i-dead-cells-i-)

今回への判断: 制作元に3Dを使う選択肢として記録するに留める。今回の既定案には混ぜない。

### S07: 室内表現 — Joost van Dongen、Humus、Harry Alisavakis

原著者は室内の面との交点を計算する方法に加え、家具用の画像層を足す例を示している。HumusとHarryの公開実装はcubemapを使う。部屋の境界と家具を分けることは既知の拡張である。

[Joostの解説と家具の図](https://joostdevblog.blogspot.com/2018/09/interior-mapping-real-rooms-without.html)、[Humusのデモ](https://www.humus.name/index.php?page=3D&ID=80)、[Harryの解説](https://halisavakis.com/my-take-on-shaders-interior-mapping/)

今回への判断: 教室写真の中に机と壁を焼き込んだまま変形する方式から、奥の壁と手前の机の画像層を分けて比較する。Spider-Manでの採用について、Joost本人も外観からの推測と明示しているので、公式な実装確認としては扱わない。

## 4. 原理の一次資料

- [Billboard Clouds for Extreme Model Simplification, SIGGRAPH 2003](https://graphics.cs.yale.edu/sites/default/files/bc03_0.pdf): 3Dモデルを複数の向きの画像面へ簡略化する。自動変換の論文と、2D部品の手動組立という応用案は区別する。
- [True Impostors, GPU Gems 3, Eric Risser](https://developer.nvidia.com/gpugems/gpugems3/part-iv-image-effects/chapter-21-true-impostors): 複数の深度をテクスチャに持ち、板を通る視線と交差させる。GPUの古い計測値を現在の性能予測には流用しない。
- [3D Photography using Context-aware Layered Depth Inpainting, CVPR 2020](https://shihmengli.github.io/3D-Photo-Inpainting/): 元画像の遮蔽物の裏へ、色と深度を追加する。深度をずらすだけで生じる穴の問題を考える資料。出力メッシュをそのまま今回へ持ち込む案ではない。
- [Stack3D作者の解説](https://dev-dwarf.github.io/dwarfdev/tutorials/2021/01/24/Stack3D-Guide.html): 画像の積層を既存方式として確認。同ページ冒頭で作者はStack3D自体の使用を勧めていない。安易な導入候補にしない。

## 6. 次の小さい実験の順序（未実施）

### A. 画像の部品分けで、椅子の回転追尾をなくす

座面・背・左右の脚を別画像面として、カメラに追従させず固定する。手描きNormalと小さいDepthを必要な部品にだけ付ける候補。正面だけ良くなる案を避け、左右、背面、上からの見下ろしを同じ距離で見る。板の隙間と二重像が残るなら保留にする。

### B. 教室を壁・床・家具の層へ分ける

既存の一枚写真の再投影を基準に、家具一層だけを追加して比較する。机と奥の壁が別々にずれ、枠による遮蔽が保たれるかを見たい。教室の全体を新規に作り直す前に一つの開口で確かめる。

### C. 同じ小物で深度一層と複数層を比べる

True Impostorsの本格実装の前に、穴や裏面がどの位置で必要かを確認する。カラーだけ、Normal追加、Depth追加を別々に比べ、光の効果と視差の効果を混同しない。

### D. 多方向Impostorは投影補正込みで再評価

画像をさらに生成して数を増やす前に、投影と深度補間の設計を確認する。Three.js全体の更新や新しいベーカーの導入は、この比較だけのためには行わない。

全て、見本｜現在｜試作の順で、同じ視点・同じ光を使う。今回は調査だけなので新しい試作画像はない。

- Joostの原理図と、室内へ人物・家具の画像層を追加した図を画面で開いて見た。層を追加しても人物自体は平面だと分かる例で、これを自由な立体復元の証拠にはしない。

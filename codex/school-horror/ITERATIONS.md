# 夜の校舎の改善記録

## 方針
2D画像を使う制約のまま、静止画と歩行時の両方で説得力を上げる。AAAは目標であり、到達の断言はしない。現段階の版を baseline.html / baseline.js に固定し、比較は方向見本（生成した構図案）｜現在（固定した旧版）｜試作で行う。構図案をゲーム映像の見本や研究の測定正本とは扱わない。

## 今回の順序
1. 壁画像の端が引き伸ばされる不具合、廊下と建具の尺度、透過素材の描画順を直す。
2. Three-Fenestra の既存 GLSL を使って教室を Interior Mapping にする。
3. Three.js r160 の Reflector、EffectComposer、UnrealBloomPass を使い、床・光・暗部をまとめる。
4. 8方向の椅子画像を切り替える既知の directional impostor を試す。生成画像の形が揃わなければ採用しない。
5. 入口、窓際、開いたドア、椅子の前後を実際に歩いて見直し、改善前後を記録する。

## 参考実装と選択
- Three.js r160 / MIT: 既存の導入版を維持し、平面反射と仕上げを公式 addons で実装。反射は描画が一回増えるため解像度を制限する。
  https://github.com/mrdoob/three.js/blob/r160/examples/jsm/objects/Reflector.js
- Three-Fenestra / MIT / d63feeb1d43fc0156d622eeb9f3e115532147113: src/shader/chunks.ts は型を含まない JavaScript のため、内容を変えず vendor/interior-chunks.js に保存。部屋写真を視線と仮想の室内深度に応じて再投影する glslCore を使う。室内画像は事前に光の付いた絵で、実際の室内模型や入室可能な空間ではない。
  https://github.com/codedgar/three-fenestra
- Drei SpriteAnimator / MIT: アトラスから表示領域を切り替える構成を参考にする。Reactの追加依存を導入する必要がないためパッケージ自体は導入しない。
  https://github.com/pmndrs/drei/blob/master/src/core/SpriteAnimator.tsx
- agargaro/octahedral-impostor / MIT: WIP。深度付き多方向キャプチャを必要とするため、生成した2D画像だけから完全な octahedral impostor が得られるとは扱わない。
  https://github.com/agargaro/octahedral-impostor
- NVIDIA GPU Gems 2 / Per-Pixel Displacement Mapping: POM/Relief の用途と限界を確認。表面の高さ用で、大きく裏側へ回る物体を一枚絵だけで完全に復元する方式ではない。
  https://developer.nvidia.com/gpugems/gpugems2/part-i-geometric-complexity/chapter-8-pixel-displacement-mapping-distance-functions

## 実画面での反復結果（今回）

1. 最初の描画では、旧版の横長で黒く抜けた空間から、学校らしい幅と高さに直せた。ただし蛍光灯の点光源が天井を白く飛ばし、椅子が浮いた。
2. 蛍光灯を弱めて位置を下げ、窓光の位置を開口に合わせた。窓からの青い光と枠の影が右壁・床へ入り、暖色の照明との区別が出た。椅子の画像内の余白を考慮して表示位置を下げた。画像ファイル自体は加工していない。
3. Interior Mapping を同じ撮影位置で depth=0 / depth=1.2 に変えて実画面を開いた。窓・机の投影が変わることを確認（shots/door-depth-off.jpg / shots/after-door-depth.jpg）。色の濃い教室画像は最初黒く潰れたため、室内の明るさと横のサンプリング範囲を直した。
4. 椅子を正面側と反対側から実際に開いた（shots/chair-front.jpg / shots/chair-back.jpg）。裏へ回っても正面画像が追尾する問題は減った。ただし生成した8枚の角度・形状は厳密には揃っておらず、切替の跳びは解消していない。完成品の素材として採用確定とは扱わない。
5. WASDの前進とドラッグの見回し、懐中電灯を実操作。描画エラーと警告の取得結果は空配列。node --check の3ファイルは終了コード0。

### 全体を揃えるルールの暫定案

- 冷たい外光と暖かい室内灯の役割を分ける。暗い所も全て黒にせず、材質の中間調を残す。
- 枠だけ明るい無照明素材にしない。同じ場所の壁と枠が同じ光を受け、奥は別の暗さになるようにする。
- 接地、開口の見込み、前後の遮蔽を先に揃える。強いbumpやBloomで奥行きの不足を隠さない。
- 床は全面を鏡にせず、窓や照明が斜めに映る程度に留める。

### 次に必要なこと

AAA品質には未到達。特に近距離の椅子には、同一物体を正しい角度で収録した方向画像と深度が必要。今回の8枚はその代用になり切れていない。自由な視点移動には、POMの高さ画像、深度付きインポスター、複数レイヤーそれぞれに素材制作の制約がある。一枚絵の裏側を自動的に正しく作れる方式として説明しない。

追加で確認した一次資料:
- Epic Impostor Baker: 多方向の色・法線・深度と、視差による改善。
  https://dev.epicgames.com/documentation/unreal-engine/impostor-baker-plugin-in-unreal-engine
- Three.js Transparency: alphaTestと深度バッファの使い分け。
  https://threejs.org/manual/en/transparency.html
- Three.js Post Processing: 既存のPassを組み合わせる。
  https://threejs.org/manual/en/post-processing.html

## v3: 固定した画像部品と室内の家具レイヤー

### 実装

- 比較元を current-v2.html / stage-v2.js に固定。
- image-chair.js: 座面・裏面・背・支持材・小口を32枚の固定画像面で組む。カメラ追尾も方向画像切替も行わない。支持材は直交する画像面で、丸い法線の近似を付ける。箱や円柱のモデルは使用しない。
- layered-room.js: 仮想の室内の面と家具画像を別の距離で引く。家具の画素が不透明な所では、手前の層が奥の面を隠す。
- 画像は組み込みimage_genで新規生成。assets/chair-parts-v3.png、classroom-wall-v3.png、classroom-desk-v3.png に保存。最終プロンプトは PROMPTS-V3.md に保存。元画像の画素加工はせず、実行時のUV切り出しで使用。

### 反復して見直したこと

1. 初回の椅子は支持材が細く、木の板の端が紙のように見えた。支持材の幅を実物の小径パイプ程度にし、座面の裏面と小口、背の裏側と小口を細い画像面として追加した。
2. 入口からは座面が真横になり、線だけに見える配置があった。椅子自体の固定向きを変えて、木と金属の面が読める位置へ置き直した。カメラに応じて向きを変える処理は付けていない。
3. 木の端と床に隙間が出たので、接地する高さへ下げた。影と床反射に椅子の各部品が入ることも実画面で見た。
4. 教室は家具なし / ありを開いて見て、さらに家具の距離を1.25m / 2.1mに変えて見た。壁を保ったまま家具の位置と大きさが変わる。机は依然として平面なので、自由な入室や裏へ回る用途には広げない。
5. 支持材の法線を0 / 0.85に変え、同じ側面位置でFの懐中電灯を点けて比較。支持材の明暗が変わることを画像で確認した。法線で外形が丸くなるわけではない。
6. 入口から前進し、椅子の横を通り、ドラッグで振り返る操作を実際に行った。画像切替に伴う形の跳びはない。前・横・後ろで画像面の重なりが変わることを確認した。

### 見た目の判断

静止画では前の生成した椅子の画像に丸みの描き込みがあり、今回の固定部品がどの視点でも一律に綺麗とは言えない。今回の利点は、移動時の形と前後関係を保つこと。近接では支持材の交差面、板の曲率不足が残る。AAA到達とは判定しない。

教室では、完成写真の中の窓や机を一緒に変形する前の方式から、床・壁・家具の距離を分離できた。机の足元は床へ合わせているが、室内の照明と家具の自己遮蔽は簡略化している。

## HD-2Dの制作事例から追加する観点

ユーザーの指摘を受け、Unreal Engine公式のAcquire / Square Enix開発者取材を確認した。『Octopath Traveler』では、エフェクトと一緒に点光源を置き、キャラクターの影を環境へ落とした工夫が説明されている。

https://www.unrealengine.com/spotlights/octopath-traveler-s-hd-2d-art-style-and-story-make-for-a-jrpg-dream-come-true

同作は2Dと3D環境を合わせた制作例なので、今回の画像素材だけの制作と同一方式とは扱わない。今回は次を応用する。

- 画像の部品も、周囲と同じ光を受け、同じ床へ影を落とす。
- 接地と遮蔽を先に読み取れるようにする。現在の椅子は固定部品が窓光の影と床反射へ入る。
- Fの懐中電灯も影を落とすようにし、画像部品を照らしたときの床・壁の影まで連動させる。torchShadow=0で比較できる。
- 近い椅子の輪郭をぼかして隠す仕上げは今回の比較に入れない。まず移動時の形と影を確かめる。

室内は簡略なシェーダーのままで、懐中電灯による室内の再照明は未対応。HD-2Dの事例を引いたことを、全要素が同じ照明系になったという説明にはしない。

HD-2Dの事例を参考に、Fの懐中電灯にも影を追加しました。画像部品を照らすと床・壁に落とす影も連動します。比較画像は shots/v3/torch-shadow-off.jpg / torch-shadow-on.jpg。最初の撮影では読み込み直後のF入力が素材読み込み前になったため、完了表示を待ってから、同じ点灯状態で影だけを切り替えて撮り直しました。

比較パラメータの画素差も補助として確認した（各481×902、RGB差8/255を超えた画素）。家具の距離: 10,705画素、支持材の法線: 7,718画素、懐中電灯の影: 9,973画素。これはパラメータが描画へ届く確認で、画質の良し悪しの点数には使わない。原記録は shots/v3/pixel-check.txt。

## v4: HD-2Dの照明の扱いを参考に、室内も再照明する

2026-10-25。出典と適用範囲は RESEARCH-2026-10-25.md。

### 反復

1. v3の室内は、廊下に懐中電灯を向けても同じ明暗だった。既存のInterior Mappingの遮光を調べ、仮想の床・壁・机の交点へ、実際のSpotLightの光を加えた。
2. 光のある版だけで判断せず、画像のドア・机による遮光を入切して撮影。机の向こう側の床や机への光漏れが抑えられる。鏡面反射用の仮想カメラに光源が追随しないよう、実際のSpotLightを参照している。
3. 最初の撮影視点では光が主にドアに遮られ、変化が小さかった。診断用のroom-light視点を追加し、旧版にも同じ位置・向きを用意した。光源の強さや壁の明るさを比較相手だけ変えることはしていない。
4. HD-2Dの開発者取材と公式画面を確認。室内の均一な環境光を改め、消灯した教室は廊下と同じ半球光・環境光を面の向きに応じて受けるようにした。懐中電灯なしでは暗く、照らした机と床が読める。天井が周囲から独立した明るい絵に見える状態は減った。一方、照らさない奥の材質はかなり読みにくくなるので、暗さは今後も実画面で評価する。
5. 実際に教室前で横移動とドラッグを行うと、最初の見回しで視点が傾く不具合を発見。回転順序の単純代入で姿勢が変わっていたため、camera.rotation.reorderで姿勢を保つよう修正。撮影し直して傾かないこと、Fの点消灯が動くことを確認。

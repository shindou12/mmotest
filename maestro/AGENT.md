# チケットを渡された AI へ（最初に読む）

あなたは Maestro のチケットを 1 枚渡された作業者です。この文書と、渡されたチケットだけで作業を始められるように書いてあります。

## 1. 準備
1. リポジトリ: `https://github.com/shindou12/mmotest`。チケットは `maestro/tickets/<id>.md`。
2. 読む順: このファイル → チケット → チケットの `## 参照` → リポジトリの `CLAUDE.md`（Claude）か `AGENTS.md`（Codex・Luna）。
3. 分野ごとの大ルール（`maestro/rules.json` の一覧と同じ）:
   - ワールドアート（地図・木・草・光）: `docs/world-art/rulebook.md`。見た目の判断は画像と数値の両方で。ユーザーに見せるのは「見本｜現在｜試作」の並び
   - 分担・委任・確かめ方: `docs/agents/collaboration.md`
   - 今の作業と引継ぎ: `docs/handoff/README.md`
   - Godot: `docs/godot/goal.md`、Windows の道具の場所は `docs/godot/windows-setup.md`
4. 言葉: ユーザーへの報告もコメントも日本語で、平易に。

## 2. 握る
チケットの先頭の `owner`（自分の会話名か名前）・`agent`・`model`・`session`・`branch` を埋め、`status: doing`・`updated` を今日にする。**チケットのファイルだけ**をコミットしてプッシュする。プッシュがぶつかって、相手がすでに `doing` にしていたら、握らずに止まってユーザーに伝える。

## 3. 進める
- ブランチは `maestro/<id>-<短い名前>`。ほかの人のブランチに直接プッシュしない。
- 節目ごと（できた・わかった・詰まった）に、チケットの `## 記録` に 1 行足す: `- <日付> <agent>（<会話名>）: <したこと／わかったこと／次>`。
- 小項目が大きすぎたら、勝手に広げず、記録に「分けたほうがいい」と書く（分けるのはオーケストレーター）。
- 範囲の外を直したくなったら、直さずに記録に書く。

## 4. 渡す
- 完了の条件を確かめ、`status: review` にして、記録に結果（確かめたこと・残り・ブランチ）を書いてプッシュする。統合（本線へのマージ）はオーケストレーターがする。
- 途中でやめるときは `owner` を空に、`status: todo` に戻し、どこまでやったかを記録に書く。

## 5. してはいけないこと
- 秘密情報（API キー・トークン）を書かない・出さない。課金・認証・外部への公開が要るときは止めて記録に書く。
- テストを飛ばして緑にしない。履歴の書き換え（rebase・force push）を他人のブランチでしない。

# Maestro（マエストロ）: 作業の工程管理

このリポジトリの作業（ワールドアート・Godot・ゲーム・道具）を、チケットとカンバンで管理する仕組み。ユーザーが見て「残りは何か・誰が何を握っているか」がわかり、AI が「このチケットのリンク 1 本から、ルールとやり方を読んで作業を始められる」ことが目的。

- **データ**は git のファイル（この `maestro/` フォルダ）。チケット 1 枚 = ファイル 1 つ。
- **見た目**はそこから組み立てたサイト（Netlify）。カンバン・チケット・ルール・アセット・担当の画面がある。組み立ては `node maestro/site/build.mjs`、出力は `maestro/dist/`。
- 役割: **ユーザー**が思いつきを入れ、優先を決める。**オーケストレーター**（指揮者。メインの会話の Claude）がチケットを分解・割り振り・統合する。**作業者**（別のセッションの Claude、Luna、Sonnet のサブエージェント、人）がチケットを 1 枚握って進める。

## フォルダ
| 場所 | 中身 |
|---|---|
| `maestro/tickets/M-0001.md` … | チケット（下の形） |
| `maestro/TEMPLATE.md` | 新しいチケットのひな型 |
| `maestro/rules.json` | ルールの画面に載せる文書の一覧（リポジトリの文書へのリンクと一言） |
| `maestro/AGENT.md` | **チケットを渡された AI が最初に読む案内**（作業の始め方・記録の書き方・終わり方） |
| `maestro/site/` | サイトの組み立て（ソース） |
| `maestro/dist/` | 組み立ての出力（コミットしない） |

## チケットの形
ファイルの先頭に、`---` で囲んだ項目を 1 行ずつ書く（YAML の簡単な形。値は 1 行）。

```
---
id: M-0001
title: Godot の起動時のバグを直す
status: todo            # inbox（思いつき・未整理）→ todo（やる）→ doing（作業中）→ review（確認待ち）→ done（済み）／ hold（保留）
priority: P1            # P1 いま / P2 次 / P3 いつか
area: godot             # world-art / godot / game / maestro / tools など
parent: M-0003          # 親のチケット（分解した子に書く。無ければ空）
owner:                  # 握っている作業者（例: Claude「アートスタイル研究_クラウド版」）。空 = 誰も握っていない
agent:                  # Claude / Luna / Sonnet / 人
model:                  # 例: claude-opus-5-5、gpt-6-luna
session:                # 作業しているセッションの URL か名前
branch:                 # 作業のブランチ
created: 2026-10-28
updated: 2026-10-28
---
```

本文は見出しで分ける:
- `## 目的` なぜやるか、1〜3 行
- `## 完了の条件` 何ができたら done か（確かめ方まで）
- `## 小項目` `- [ ]` のチェックの並び（オーケストレーターが分解する。大きくなったら子のチケットに分ける）
- `## 参照` 読むべきルール・文書・関連のチケット
- `## 記録` 1 行ずつ追記: `- 2026-10-28 Claude（会話名）: 何をした／何がわかった／次`

## 進め方の決まり
1. **思いつき**: ユーザーは GitHub の Issue に `maestro` のラベルで 1 行書くか、オーケストレーターに話す。オーケストレーターが `status: inbox` のチケットにし、整理して `todo` にする。
2. **握る**: 作業者は `owner`・`agent`・`model`・`session`・`branch` を埋め、`status: doing` にしてコミット・プッシュする。**プッシュがぶつかったら、先に握った人がいる**ので取り直さない。1 人が同時に握るのは 1 枚。
3. **進める**: 作業のブランチは `maestro/<id>-<短い名前>`（例 `maestro/M-0001-godot-boot`）。節目ごとに `## 記録` に 1 行足す。小項目にチェックを入れる。
4. **渡す**: 終わったら `status: review` にして、`## 記録` に結果（確かめたこと・残り）を書く。オーケストレーターが確かめて統合し、`done` にする。
5. **やめる**: 途中でやめるときは `owner` を空に戻し、`status: todo` にして、どこまでやったかを記録に書く。

チケットの状態を変えるコミットは、チケットのファイルだけを含める（作業の変更と混ぜない）。

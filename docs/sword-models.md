# 採用した片手剣モデル

作業ブランチ: `codex/swords-refined`。通常剣の確認結果は全3系統Aを採用。
以後のリファインは1種類につき1案で行い、今回のユニーク剣も各1モデル。
最新 `refactor/solid` のボス定義シート（`f10cca7`）も取り込んでいる。

| style | 表示対象 | 造形 |
|---|---|---|
| 0 | 通常直剣 | 承認済みの細身A |
| 1 | 通常刀 | A。細い片刃・反り・横に寝た鍔・巻き柄 |
| 2 | 通常葉形剣 | A。上寄りのふくらみ・中央の稜線・葉形の柄頭 |
| 3 | 固有IDのない旧形式・未対応の伝説/神器 | 既存の共通形を保持する互換用 |
| 4 | `amenomurakumo` 天叢雲剣 | 古い両刃の神剣、雲の巻いた鍔、青緑の柄、勾玉の柄頭 |
| 5 | `durandal` デュランダル | 象牙色の鋼、端正な十字形、青い握り、盾状の中央金具 |
| 6 | `laevateinn` レーヴァテイン | 黒い波状の刃、炎の芯、枝分かれした黒鉄の鍔 |

通常剣Aは選択時の全8品質×3系統の形状記録と一致する。
刀・葉形剣の本番生成と昔の比較画面は同じ採用モデルを参照し、Beforeの形だけ履歴として保持する。

## 表示の経路

`weaponStyle(item)` が装備の既存 `unique` IDを `shared/weapon-appearances.js` の固定番号へ変換する。
既存の `wst` フィールドで他プレイヤーへ送るため、追加の通信フィールドやセーブ移行は不要。
サーバーは武器種に対応する許可済み番号だけを受け付ける。他の武器種は0〜3を継続する。

自分・他プレイヤー・落とし物はいずれも同じ `makeWeapon` の登録表を使う。
同レア度の固有剣同士でもstyleが異なるので、持ち替え時にモデルが更新される。
未知の固有IDやIDのない古い装備は従来のstyle 3で表示できる。
武器の数値・スキル効果・攻撃タイミングは既存の内容を使う。

形の共通部は `models/sword-geometry.js`、通常刀・葉形剣は `models/sword-forms.js`、固有3本は `models/unique-swords.js`。
クライアントの描画用KITから登録し、サーバー共通の武器定義へThree.jsを読み込まない。

## HTMLで確認

`npm start` 後、`http://localhost:8080/swords-refined.html` を開く。
通常剣/ユニーク剣、単体/旧形との比較/装備/握り/ゲームカメラを切り替えられる。
初期は静止。Playと時間スライダーで、ゲーム本体の通常3段・溜め・スラントラッシュを確認できる。
UIはRoot配下のPassive View、イベントの親への伝播、状態機械Mediatorによる処理で構成する。

## 検証

- `npm test`: 79件成功。
- 通常剣は承認時の24モデルと完全一致。新規固有3本は閉じた刃・外向きの面・有限な頂点・寸法・描画コールを確認。
- 3本の装備/ドロップでの選択、旧データの表示、同レア度での持ち替え、握りの位置と向き、許可番号の同期と不正値の除外をテスト。
- 2ブラウザのオンライン接続で通常3系統と固有3本を順番に装備し、自分と相手の双方で同じモデルが選ばれることを確認。
- 実ゲームの描画、HTMLの全モーション・握り・角度・再生停止・スマートフォン幅を確認。
- 画面・セーブの既存E2Eに一致。描画の記録は通常刀・葉形剣に関する3項目だけ更新。
- モデルの記録は通常刀・葉形剣と葉形剣の装備者の17項目だけ更新。骨格・スキル・サーバーの既存記録は変更なし。

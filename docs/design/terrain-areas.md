# 地形エリア（平坦・円形からの脱却）設計

試作「ひだまりの谷」（proto/stage.html）のような、起伏と自由な形のエリアを、ゲームで遊べるようにする。
まず 1階の草原（f1_field）を置き換えて試し、良ければほかの屋外エリアへ広げる。

## 1. 今の前提（調査結果）

| 仕組み | 今 | 場所 |
|---|---|---|
| 外周 | 中心からの角度ごとの半径（楕円＋ゆらぎ）。`boundR` / `insideOpen` | shared/areas.js |
| 当たり | `collide(def,x,z,rad)` が唯一の入口。屋外は「障害物の円から押し出す＋外周の半径で止める」 | shared/areas.js:625 |
| 配置 | 敵の出現・障害物・危険地帯・宝箱・出口・到着地点・ワープ地点が、すべて「角度＋半径の割合」 | areas.js / sim/area-tick.js |
| 敵の移動 | 屋外はまっすぐ向かう＋障害物を横によける。迷路（grid）は幅優先探索 `pathStep` | sim/mobs.js:245-263 |
| 高さ | クライアントだけ（`heightAt`）。サーバーは高さを知らない | env/kit.js・game/area.js |
| 地図 | 外周を64点の多角形で描く | ui/panels/minimap.js |
| カメラ | 外周の外に出ないよう、カメラを引く距離を縮める | game/loop.js:420 |

良い点: 当たりは `collide` の1か所、迷路の探索 `pathStep` もある。サーバーはプレイヤーの位置を信じる（移動の当たりはクライアント）。

## 2. 方針: 新しい形 `shape: 'terrain'`

### 2-1. 地形の定義を shared へ
- 高さの関数（試作の `heightAt`）を **shared/terrain/** に置き、サーバーとクライアントで同じものを使う（決定的。乱数なし）。
- エリアの定義: `{ shape: 'terrain', terrain: 'meadow', size: [220, 170], exits: [{ to, x, z }], spawns: [...], ... }`
  - 出口・到着・ワープ・宝箱・敵の出る場所は **座標で直接書く**（角度＋割合はやめる）。

### 2-2. 歩けるかどうかの格子（ナビ格子）
- 1m 間隔の格子を、高さの関数から一度だけ作る（220×170 = 約3.7万マス。起動時に数十ms）。
- 歩けないマス: **急な斜面（崖）**・**深い水**・**外周の山**・**固い障害物**。橋の上は歩ける（橋はデータで「歩ける帯」として上書き）。
- `collide` の terrain 版: 迷路と同じく、周りの歩けないマスから押し出す（マスが小さいので、角が目立たないよう 2回押す）。
- `insideOpen` の terrain 版 = 「歩けるマスか」。
- 敵の移動: 迷路の `pathStep` を、粗い格子（2m）で使う。見えている・近いときはまっすぐ（今と同じ）、崖をはさむときだけ探索。

### 2-3. 高さの扱い
- 当たり・距離は今までどおり平面（x, z）。**崖の上と下は格子で分かれる**ので、崖越しに殴り合うことはほぼない（遠距離は届く。これは「高台から撃つ」として味にする）。
- 見た目: キャラ・敵・落とし物・予兆の円は `heightAt` に載る（今の仕組みのまま。予兆はすでに地面に沿って曲がる）。
- 弾: 今は高さ1mで飛ぶ → 「地面から1m」に変える（坂で地面に埋まらないように）。

### 2-4. 戦う場所
- 敵の出る場所は「広く平らな場所」をデータで指定（試作の中央の草地・台地の上・川の北の林の空き地・東の滝つぼ）。
- 崖・川は戦いの地形になる: 坂道や橋が狭い道になる、台地は遠距離が有利。

### 2-5. 地図・カメラ
- 地図: 歩けるマスを小さな画像に焼いて表示（崖・水・山は色分け）。
- カメラ: 外周の山で視界がふさがらないよう、カメラの位置の高さを地形より上に保つ（近景の透過は今のまま）。

## 3. 進め方
1. shared/terrain/meadow.js（高さ・水・橋・道）と、ナビ格子・`collide`・`pathStep`・配置を terrain 対応に。
2. f1_field を terrain に置き換え（今の f1_field の出口4つ＝町・狩場・古井戸・迷宮区を、谷の入口・東の岩山の上・西の切り通し・台地の奥に置く）。
3. 見た目は試作の組み立てを env/ に移す（`shape: 'terrain'` のとき使う）。
4. 地図・カメラ・弾の高さ。
5. テスト: ナビ格子（崖が歩けない・橋は歩ける・出口から中央へたどれる）、敵が崖の上下をまたいで湧かない、全エリアの記録テストの作り直し（f1_field 分）。

## 4. 自己評価

| 観点 | 評価 | メモ |
|---|---|---|
| 効き | 高 | 「平らな丸い広場」から抜けられる。崖・橋・坂が戦いの場にもなる |
| 手間 | 大 | shared の配置まわりと敵の移動、地図、見た目の移植。f1_field 1か所でまず数日分の作業量 |
| 危険 | 中 | 敵が崖の下で詰まる（探索で対処）。重さ（格子の探索は粗くして回数を抑える）。プレイヤーの位置はクライアント任せなので、当たりのずれは今と同じ程度 |
| 既存への影響 | 小 | 新しい形を足すだけで、ほかのエリア（open・grid）はそのまま。f1_field だけ置き換え |
| 記録テスト | 要作り直し | f1_field を使う戦闘の記録（武器の試し斬りの場所が f1_field）→ 試し斬りの場所を平らな所に置くか、記録を作り直す |

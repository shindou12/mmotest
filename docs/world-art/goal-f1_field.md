# ゲームの第 1 層「ひだまりの草原」（f1_field）を第 3 世代で作り直す（L25）

ゲーム本体（`public/shared/areas.js` の `f1_field`、街を出て最初の屋外エリア）を、規則集（`rulebook.md`）で作り直した記録です。
見本の 1 枚を似せるのではなく、**ゲームの遊びの形を保ったまま、規則だけで歩ける地図を作れるか**を確かめるのが目的です。

## 作り方
| 手順 | 道具 |
|---|---|
| 1. ゲームの形を書き出す: 輪郭（boundR を 1° ごと）・出口 4 つ・当たり判定の木 11 本と岩 1 つ・宝箱 2 つ・出現位置・ワープポイント | `node tools/worldart/maps/dump_area.mjs f1_field` |
| 2. 地図の JSON を書く（雛形 + ゲームの形 + 演出） | `python3 -I tools/worldart/maps/make_f1_field.py` → `public/worldart/maps/f1_field.json` |
| 3. アセット（新規 7 つを含む全 70 個を Blender で作り直し。既存の GLB はバイト単位で同じ） | `blender -b --factory-startup --python tools/worldart/blender/build_assets.py` |
| 4. 地形と配置 | `blender -b --factory-startup --python tools/worldart/blender/build_map.py -- f1_field` |
| 5. 撮る（作り直した絵 / ゲームの今の絵） | `node tools/worldart/views.mjs f1_field art/shots/f1_field/Lnn OV,F01,…,F07` / `node tools/worldart/gameshot.mjs f1_field f1_field art/shots/f1_field/game` |
| 6. 並べる | `python3 -I tools/worldart/pairsheet.py art/shots/f1_field/game art/shots/f1_field/L25c art/shots/f1_field/compare_game.webp F01,…,F07` |

ゲームのままにしたもの: 輪郭、出口の位置、当たり判定のある木・岩の位置と大きさ、宝箱、出現位置、ワープポイント、道の曲がり方（中心から出口へ、横に `sin(along*0.12)*2.5`）。
地図の JSON の `game` に、これらの元の値を残している。木・岩の `solid`、宝箱の `chest`、門の `exit`、石柱の `waypoint` はゲーム側と対応させる印。

## わかったこと（規則への反映）
1. **歩ける広い地図では、道を樹冠で縁取らないと、ほとんどの画面が「草と道だけ」になる**。見本②のように 1 枚の構図を決めて木を置く方法は使えない。道ばたの木（道の縁の 2.2〜3.5m 外、5〜9m おき、左右を入れ替えながら 1〜3 本）で、開けた道のビューの暗い所が 3〜7% → 12〜16%、明暗比 1.6〜2.2 → 2.4〜2.6（rulebook 10.2 に追加）。8〜14m おきでは足りない。
2. **遊びの形を変えずに外周を作る方法**: ゲームの輪郭のすぐ外を地形の岩肌の段（3m）+ 林にし、出口は段を切った谷（`cliffs[].gaps`）。灰色の岩の壁より、見本の「崖の向こうも林」に近い（rulebook 7.1・10.2 に追加）。
3. 集まる場所（ワープポイントの広場）は開けたままにする。画面の目標（暗い所 13〜17%）に入らないが、遊びの都合を優先した（制約として記録）。

## 残り
- F02 の広場（明暗比 1.59）: 広場の外周に木の影を落とす木を置くか、広場は例外として扱うかを決める。
- 柵が道ばたの木の幹を突き抜ける所がある（柵と木の配置の順番。木を柵の線から避ける）。
- 道しるべの板が細く、上からは枯れ枝に見える（板の幅・色）。
- 地形はゲームの `heightAt` と別（外周の段・起伏）。ゲームに組み込むなら、歩く高さを地図の高さマップから取る必要がある。ゲームへの組み込みは未着手。
- 太陽の方位は雛形のまま（70°）。ゲームの第 1 層の空・霧の色とは合わせていない。

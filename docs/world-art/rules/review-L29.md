## 1. 今の地図を見本と並べて見た（mihon2、B01・B03、occR=0、既定の引数）
撮影はクラウドのソフトウェア描画（1 枚 ≈ 2.5 分）。見た印象:
- **B03 の崖がいちばん離れている**。見本の崖は苔と草が上からかぶさる丸い岩の塊で、岩と緑が混ざる。こちらは灰色の平たい多角形の面が並び、緑とはっきり分かれる（「分離感」の一番大きな出どころ）。
- **地面の大きな明暗**: 見本は林の床・樹冠の下・画面の縁が暗い緑に沈み、明るいのは道と開けた所だけ。こちらは地面全体が明るい黄土色で、暗いのは落ちた影の形の中だけ。影の縁がくっきりしている。
- **樹冠**: 見本は丸い房の塊ごとに明暗が移る。こちらは房の中の細かい葉の模様が先に見え、明るさが均一。
- **草の房**: こちらは明るい黄緑の房が地面から浮いて見える。見本では草地は地面の絵として読め、房は目立たない。
- ヤシ・テント・木箱の大きさと配置は近い。

## 4. 見直してわかったこと
1. **研究が 2 つに分かれた**。L27・L28 は「地図全体を見本に近づける規則」、Codex は「1 本の木・1 つの部品を良くする」。部品の良し悪しは地図の中で並べないと決まらない（L27 の教訓）ので、次は**良い評価の部品を地図に入れて見本と並べる**のが早い。
2. **絵を描く手段が決め手**。手続きの描画は限界が見えた。画像生成の絵は評価が高い。ただしこのクラウドの環境には画像生成も Blender も無い。絵とアセットの作り直しは Codex（Windows）側、three.js 側の描き方・地図への組み込み・比べる作業はこちら、と分けるのが現実的。
3. **B03 の崖は L27 以降手つかず**。rock_mass の失敗は「塊の明暗まで消した」ことで、岩を量感で描く方向そのものは否定されていない。見本の崖は「苔と草のかぶさり」「岩と緑の混ざり」が大きい。
4. 地面の大きな明暗（林の床が沈む）は、L27 の bake（空の見え方のベイク、6 点）と同じ向き。全体の仕上げではなく「樹冠の下の地面」に限れば、天候の話ではなくスタイルの規則として効くかもしれない。

## 6. 輪郭線（2026-10-28、ユーザー）
- ユーザーの方針: **RO の再現としてではなく、背景をよりトゥーン調・スタイライズに寄せる手として輪郭線を採るのもあり**。人物はもともとトゥーンと輪郭線なので、背景にも線があれば画面がそろう可能性がある。
- 見本を原寸で拡大して見た: 黒い線の輪郭は無い。葉の層の下・岩の割れ目・物が奥に重なる縁が暗く沈んで、線のように読める。「輪郭線を足す」と「重なりの縁を沈める」は別の手として試せる。
- テストページ（Artifact）: https://claude.ai/artifact/MgP1ESFfSiQJTpZuobdY5A 。Codex の `codex/outline-blend` を `tools/worldart/compare/outline/build.py` で写したもの。上が輪郭なし（今の地図）、下が試作（外形・奥行きと面の境界・外側の殻、線の色、ガッシュ風）。見本の拡大も付けた。

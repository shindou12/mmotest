## 1. 目指している見た目（ユーザーの言葉）
- **研究の目的:**
  - 参考画像（Ragnarok Online 3 のキャプチャ）の見た目を解くこと。
  - **どの地図にも使える規則**と制作の流れを得ること。
  - 見本 1 枚を似せることは目的ではありません。
  - 人物（トゥーンと輪郭線のまま）と UI は対象外です。
- **エピックの「今」:**
  - 「RO3・原神を目指すスタイライズの研究」。
  - 「暗い木の塊で囲む配置と、影の色・やわらかい段の組み合わせが本命。次: 実際の地図と人物を置いて確かめる」（Maestro E10）。
- **2026-10-23 のユーザーの言葉:**
  - 「数値を合わせるゲームじゃない」「機械的に近づけようとしている」。
  - 素朴な印象として、「こちらは地面・崖・木・木箱が全部ぱきっとしていて、見本はにじみ・淡さ・ぼけがある」。
- **カメラ（ユーザー、2026-10-23）:** 回転しない、固定の向きが前提です。カメラに向けた板、光を描き込んだ絵、見えない裏側の省略も使えます。
- **地面の草（ユーザー、2026-11-07〜08）:**
  - シェルの草に対して「シェルが点々になってる」「全部点なんだよね」。
  - 直した後に「草自体なくなってない？」「普通に真上に伸ばして生い茂らせてほしい」。
  - 続けて「このやり方であってるのんか？スタイライズドな地面に生える草について、一旦車輪を探してくれ」。
  - 調べた後に「腰の高さぐらいの草が広がる草原も作って。緩やかな起伏がある感じの」（これが tall_meadow）。
- **小物（ユーザー、2026-11-02）:**
  - 形で細部（縄・切り欠き）を足した柵に、「かなり見た目が気持ち悪い」。
  - ユーザーの案は「形は幅の広い面まで、細部は絵に描く」です（`rules/fence-m0156.md`）。
- **木（ユーザー）:**
  - 手続きで描いた手のひら形の葉に、「めちゃくちゃきしょい」。
  - もみについて、「シダに見えた」「同じ形を並べない」「枝は垂らす」（何度も）。
  - 広葉樹は「案 B + Luna の絵が一番いい」（`rules/maple-b-luna-m0172.md`）。
- **岩（ユーザー）:** Luna に形を任せた岩（M-0163）に「全然うまくいってない」。
- **採用の範囲（ユーザー、2026-11-06）:** 「採用できそうなやつは採用しちゃって」。これで影の色と段、シェルの草・筋・斑、やわらかい影、露出 1.15 が、地図の既定に入りました。
- **アイコン:** 画像生成はもうしません（ユーザー、2026-10-22）。生成した絵は見本にせず、部品として使います。

## 3. 今の画面
- **ブランチ:** 研究の最新は `dev` です。M-0184 まで、2026-11-10 に取り込みました（e9ca9ac）。
- **画面の場所:** 判断に使ってきた画面は、2 つあります。
  - **three.js（web）**: `public/worldart/index.html?map=<名>`、`world.js`。L26 まではこちらで判断していました。
  - **Godot 4.3**: `godot/worldart/`。M-0180 以降は Godot に移して詰めています。
  - f1_field について、Godot と three.js は輝度 ±0.03 で一致していました（L26 の時点）。
- **起動（Windows）:**
  ```sh
  "$LOCALAPPDATA/Programs/Godot_4.3/Godot_v4.3-stable_win64.exe" --path godot/worldart scenes/main.tscn -- --map=f1_field
  ```
  - 地図を変えるときは `--map=` に `f1_lake` か `tall_meadow` を指定します。WASD で歩けます。
  - 撮影は、`_console.exe` に `--resolution 1920x1080` と `--shot=F01,near@F01,walker@F01 --out=<絶対パス>` を付けます。
- **地図:**
  - **f1_field**: ゲームの第 1 層「ひだまりの草原」を、遊びの形のまま作り直した地図（`goal-f1_field.md`）。
  - **f1_lake**: 湖畔（水の規則 w1）。
  - **tall_meadow**: 2026-11-08 に新しく作った地図。腰の高さの草とゆるやかな丘です。
- **今の既定（f1_field・f1_lake・雛形 `templates/map-gen3.json` の `style`）:**
  - 影の色と明暗の段（M-0178）。
  - やわらかい影（vsm 半径 40）、露出 1.15。
  - シェルの草（M-0179〜M-0183）: 16 層、高さ 0.28m。M-0183 から、1 本ずつ楕円の葉です。
  - 数 m の斑、道の縁の帯（gedge 1・gwide 2）。
  - なびく筋 `gcomb` は 0 にしました（M-0183。草を真上に立てるため）。
- **地面の草の今の作り（Godot）:**
  - **シェル:**
    - 8m の区画に分け、カメラの視野の外は描きません。
    - 距離で層を減らします（近い所は全層、遠くは半分、1/4）。
    - 草の三角形だけに貼り、影は落としません。
  - **tall_meadow の草:**
    - 1 本ずつ形のある葉を、MultiMesh で約 42 万本並べています（`shaders/grass_blade.gdshader`、`world.gd`）。
    - 塊ごとに、高さ・傾き・色がそろいます。
    - 法線は上向きです。
    - 根元は地面の色にしています。
    - 道の縁では間引きます。
    - 距離で減らします。
    - 下に 0.16m のシェルを敷いています。
- **今の画面で見えていること**（作業者の目視、2026-11-08）:
  - tall_meadow:
    - 葉が幅広く、色がのっぺりしています。
    - 細かい暗いざらつきがあります。
    - 低い視点だと、遠くの丘に草がありません。
    - ラベンダーが埋もれ気味です。
    - 固定の視点に木があまり入っていません。
  - f1_field の F01 は、寄ると草の楕円の粒が見えます（`art/shots/ground_m0183/v2/near_zoom.jpg`）。
- **重さ:** FPS は画面の更新の上限（144）で頭打ちです。草の前後の差は測れていません。

**草について調べた外部の手法（2026-11-08、`sources.md`）:**
- シェルは短い毛・苔向きで、背の高い茂った草は 1 本ずつの形（Breath of the Wild、Ghost of Tsushima）で作られることが多いです。
- 地面となじませるやり方として、次のものがありました。
  - 法線を上向きにする。
  - 根元を地面の色にする。
  - 塊（ボロノイ）ごとに高さ・向き・色を共有させる。
- 主な出典:
  - hexaquo の grass rendering series
  - 2Retr0/GodotGrass（MIT）
  - GDC 2021「Procedural Grass in Ghost of Tsushima」

## 6. 道具と環境（Windows の PC）
- **場所:** Godot 4.3、Blender 4.2.23、Node 22、Python 3.13 です。場所は `docs/godot/windows-setup.md` にあります。
  - Blender は `$LOCALAPPDATA/Programs/blender-4.2.23-windows-x64/blender.exe` です。PATH にはありません。5.2 は使っていません。
- **地図の流れ:**
  1. `public/worldart/maps/<名>.json` を書く。
  2. `tools/worldart/blender/build_map.py` で組み立てる。
  3. `tools/worldart/godot/export_godot.py` で Godot へ書き出す。
  - 手順は `pipeline.md` にあります。
- **撮影と比べる道具（web）:**
  - `tools/worldart/views.mjs` / `shot.mjs`
  - `compare.py` / `rulecheck.py` / `refstats.py` / `abcompare.py`
  - 見本との比較ページの元は `tools/worldart/compare/`。
- **アセット（Blender のスクリプト、`tools/worldart/blender/`）:**
  - 木: `tree_plate_build.py`、`leaf_align.py`
  - 小物: `*_blockout.py`
  - 柵: `build_fence.py`
  - 岩の焼き込み: `rock_mask.py`
- **絵の生成:**
  - Luna（`sh tools/agents/luna.sh`）は image_generation ができます。
  - 作った絵は `art/painted-gen/` にあります。
  - ユーザーにもらった手描きの絵は `art/painted-src/` です（見本にはしていません）。
- **ユーザーの決まり（`~/.claude/CLAUDE.md`・リポジトリの `CLAUDE.md`）:**
  - 一から組む前に、定番の手法と似たオープンソースを調べる。出典は `sources.md` に書く。
  - API キーの従量課金は使わない。
  - 見本の画像を外部へ送る・公開するときは、ユーザーに相談する。
  - Maestro のチケットで作業する。

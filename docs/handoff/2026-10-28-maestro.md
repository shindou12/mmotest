# 引継ぎ（2026-10-28）: 工程管理サイト Maestro を専用リポジトリで作る

前の会話: 「アートスタイル研究_クラウド版」（claude/art-style-L29）。この文書だけで始められるように書いた。

## 1. 目的（ユーザー）
複数のセッション・AI・工程の進み具合を、ユーザーが見やすく、AI が管理しやすい形で管理する。アジャイルのカンバンとチケット。
- 残り作業なんだっけ → 見る → これが残ってる
- 思いついた → チケットとして入れる → AI が予定を管理（分解・指示出し・細かい項目に）
- ルールやアセットはどうなってる → 見られる
- 誰が今どの作業を握ってる → チケットに進捗・セッション名・AI 名・モデル
- このチケットやりたい → リンクを AI に渡すと、関係ない AI でもルールとやり方がわかり、記録を残しながら出先で作業できる
- メインのオーケストレーター（指揮者）が変更を巻き取れる

## 2. 決まったこと（ユーザー、2026-10-28）
- 名前は **Maestro**。リポジトリは **`shindou12/maestro`（非公開）**。ユーザーが作る（この環境の GitHub の権限では作れなかった）。
- **ユーザーが見る・触るのはサイトだけ**。チケットの追加・状態・メモもサイトから。変更は適宜反映される。
- **会話のトークンを少なく**。ユーザーへの報告はサイトに寄せ、会話では短く。
- **computer use なしで誰でも触れる**: 人には普通の画面、AI には API（URL と鍵だけで読み書き）。
- データは git でよい。**見た目は良く**。
- **ホスティングは Netlify**（ユーザーがつなぐ。設定は Claude が文書にして渡す）。
- **サイトは Claude（Opus）が自分で作る。Luna に任せない**。まだ着手していない（試作は下の 4）。
- ユーザーの iPhone は古い iOS で、claude.ai の Artifact が開けない。サイトは古い Safari でも動くこと（ES モジュール・import map・`?.`・`??`・`:has()`・flex の gap を避ける）。

## 3. 設計の案（新しい会話でユーザーと決める）
- **Netlify のクレジット**: 新しい料金体系では、デプロイのたびにクレジットを使う（正確な数は Netlify の料金ページで確かめる）。チケットの変更ごとに組み立て直す作りにしない。
- 画面は静的に 1 回置く。データは **Netlify Functions** が GitHub の API で `tickets/*.md` を読み書きする（表示のたびに読む。書き込みはコミット）。
- 鍵: Netlify の環境変数に `GITHUB_TOKEN`（fine-grained、maestro リポジトリの contents の読み書きだけ）と `MAESTRO_KEY`（書き込みの合言葉。ユーザーのブラウザは一度入れたら保存、AI は環境に持つ）。トークンは会話に出さない。読むのにも鍵を要るかは決める（Netlify のパスワード保護は有料）。
- API の案: `GET /api/tickets`・`GET /api/tickets/:id`・`POST /api/tickets`・`PATCH /api/tickets/:id`（状態・握る・小項目）・`POST /api/tickets/:id/log`。握るときはぶつかりを防ぐ（GitHub の sha の一致で先勝ち）。
- 複数のリポジトリの作業を扱う: チケットに `repo`（例 shindou12/mmotest）を持たせる。ルール・アセットの画面は各リポジトリの文書へのリンク（maestro の `rules.json`）。
- AI の案内（`AGENT.md`）は、API の使い方と、チケットの握り方・記録の書き方・渡し方。

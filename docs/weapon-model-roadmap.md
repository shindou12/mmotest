# 武器モデルの現状と制作順

調査の基準は `refactor/solid` の `71ff612`。調査時点の一覧と、制作の計画・進捗を記録する。

## 現在ゲームで使う形

基本・互換枠は6武器種 × 4系統 = 24系統。これに固有片手剣3本を加え、27形状を表示できる。色・発光・飾りの変化は別モデル数に含めない。
盾槍の盾は別に1形 (`kite`)。構え・通常攻撃・スキルは同じ武器種の中で共有する。

| 武器種 | style 0（基本） | style 1 | style 2 | style 3（伝説・神器の共通形） |
|---|---|---|---|---|
| 片手剣 | 細身の直剣A | 刀A | 葉形剣A | 旧形式の互換形（固有3本は個別形へ接続済み） |
| 大剣 | バランス型大剣 | 大包丁 | ツヴァイハンダー | 炎の波刃（フランベルジュ） |
| 短剣 | 短い片刃 | クナイ | クリス | 月形の双刃 |
| 盾槍 | 槍・房飾り | ハルバード | 三叉槍 | 翼付きの光の槍 |
| 大斧 | 左右で大きさの違う両刃斧 | 髭斧 | 戦鎚 | ルーンの大三日月両刃 |
| 弓 | 基本の湾曲弓 | リカーブ | ロングボウ | 三日月・刃の翼 |

主要な形状定義は `public/js/weapons/<kind>.js` の `model(kit)`。
`models/weapon-models.js` が集め、`models.js` の `makeWeapon(kind, rarity, style)` が材質と仕上げを渡す。
4段階トゥーン、共通の輪郭線を使い、ゲーム内ではGLBを読まずコードで形を作る。

## 見た目の割り当てにある課題

`weaponStyle(item)` は通常武器を名前のハッシュで0〜2に振り分ける。
伝説・神器（レアリティ6・7）は、固有名に関係なく3にする。
片手剣の3本は個別モデルへ接続済み。他武器種の固有モデルは後続の制作対象。

| 武器種 | 既存の固有武器 |
|---|---|
| 片手剣 | 天叢雲剣、デュランダル、レーヴァテイン |
| 大剣 | エクスカリバー、ダーインスレイヴ |
| 短剣 | 月詠ノ小太刀、妖刀 村正 |
| 盾槍 | グングニル、ゲイ・ボルグ |
| 大斧 | ラブリュス、雷斧ミョルニル |
| 弓 | 与一の弓、アルテミスの銀弓 |

- アイテムには既に `unique` という安定したIDがある。
- 片手剣の固有IDは共有表でstyle 4〜8に変換し、既存の表示・同期・ドロップ経路を通す。
- 地面のドロップと投擲する斧の見た目にも同じ選択の仕組みを通す必要がある。
- 色や発光だけで違いを作ると、固有名の印象が弱くなる。遠目で読める外形を優先する。

## これまで作った試作

以下は制作履歴として確認できた試作。直剣A・刀Aの方向性は本体へ反映済み。月潮・バルムンク・グングニルなどの独立試作は引き続き未登録。
既存の画像・動画・GLBの配布素材と、ゲームで使う生成コードの統合は別工程。

| 試作 | 候補数 | 使い道・注意点 |
|---|---:|---|
| 一般的な直剣（標準・細身・幅広） | 3 | 片手剣の基準とバリエーションの候補 |
| 刀（細身・頑丈） | 2 | 既存の刀の解釈と置き換え候補 |
| 翼鍔のユニーク剣（Seraph / Crystal Wing） | 2 | style 3の解釈候補。特定の固有アイテムとの対応は未決定 |
| 月潮（デフォルメ改良版） | 1 | 世界観のある新規片手剣。現行アイテムには未登録 |
| バルムンク | 1 | 竜鱗モチーフの新規片手剣。現行アイテムには未登録 |
| グングニル | 1 | 既存の固有ID `gungnir` に結び付ける有力候補。盾は別途必要 |

合計10候補。月潮の旧版は同じ案の制作履歴なので数に足さない。
試作のユニーク剣コードは旧6段レアリティの4・5を前提にしている。
採用時は現在の8段（伝説6・神器7）へ直し、輪郭の二重付与と材質の共有も確認する。

## 進め方

### 1. 比較の基準を片手剣で固める

最初は片手剣style 0の1枠に絞る。既存の直剣試作を再利用して、現行と2案を並べる。
Aは現行の細身・簡潔な金具を保った改良、Bは少し太い刃と大きな色面で視認性を上げた案。
通常のゲームカメラで、待機・通常3段・溜め・スキルを同じ条件のスクショまたはHTMLで比較する。
単体の接写だけで採用を決めない。

採用の基準は、外形、金属と柄の色面、握りの接続、体との干渉、動いたときの読みやすさ、描画負荷。
形を比べる段階ではモーションと戦闘性能は変えない。

### 2. 固有武器を個別に選ぶ経路を作る

`item.unique` と対応する小さなモデルIDを使い、レアリティと形を独立して選ぶ。
既存データにIDがない場合は、今のstyleへ戻れるようにする。
自分の装備、他プレイヤー、地面のドロップ、投擲物まで同じ選択を通す。
通信には許可したモデルIDだけを載せ、古い保存データでも表示できるようにする。
この準備ができてからグングニルの試作を正式に接続する。

### 3. 武器種ごとに一巡する

推奨順は **片手剣 → 盾槍と盾 → 弓 → 大剣 → 大斧 → 短剣**。

- 片手剣: 基本直剣で基準を決め、刀の試作を調整、未作成の葉形剣を補う。
- 盾槍: 槍先・柄・盾のまとまり。グングニルと通常槍の差を外形で出す。
- 弓: 弦と描画中の矢の接続、引き手、胸との間隔を守って3つの通常形を磨く。
- 大剣: 4系統の基本モデルをリファイン済み。大包丁の塊感とツヴァイハンダーの長さを外形で分け、両手の位置を維持。
- 大斧: 髭斧・戦鎚・両刃を区別し、投擲中にも形が読めるようにする。
- 短剣: 小さくても読める刃と柄の比率。クナイ・波刃・小太刀を同じ形に寄せない。

各武器種で「基本形の品質を決める → 残りの通常形を揃える → 名前と意図に合った固有武器」を1まとまりにする。
最初から24枠すべてに2案ずつを量産しない。比較は現行+2案、採用は1案を基本とする。
固有剣の共通翼形をすべての固有名へ使い回すことは避ける。

### 4. 見た目の登録と検証

握り位置・軸・既存のIKを保ち、外形を変える場合は既存の攻撃距離との違和感も見る。
低品質設定でも外形と色で識別でき、発光や細い模様に頼らない造形を目指す。
新しい形に対応する期待値だけを更新し、既存のプレイヤー骨格・手の接続・攻撃タイミングを保護する。
オンラインで2人が同じ武器を同じ形で見られることを確認してから採用する。
比較画面を拡張する場合も、Root階層・Passive View・イベントのバブリング・状態機械Mediatorで作る。

直近の完了対象は、**大剣の基礎4系統**。次は大斧へ進み、通常3系統の外形をリファインする。


## 制作の進捗

- フェーズ1: `codex/sword-refine-phase1` で現行・A（細身）・B（幅広）を比較。通常直剣にはAを選択。
- フェーズ2: 当ブランチで、通常直剣をAへ置き換え、右手の握りと待機・溜めの構えを修正。詳細と確認用HTMLは [sword-grip-phase2.md](sword-grip-phase2.md)。
- 通常剣の一括レビュー: 当ブランチで刀・葉形剣の各2案を制作し、直剣を含めた比較HTMLに収録。詳細は [normal-swords-review.md](normal-swords-review.md)。
- 採用: 通常剣はすべてAに確定し、本体へ差し替えた。以後は1武器につき1案で制作する。
- 固有片手剣: 天叢雲剣・デュランダル・レーヴァテインの3本を個別モデルへ接続。詳細は [sword-models.md](sword-models.md)。
- 鬼牙・双星剣: 片手剣の固有モデル/アイテムとして追加し、既存の装備・ドロップ・同期経路へ接続。
- 大剣: 基礎4系統の形状を一案ずつリファイン。比較HTMLは `public/greatsword-refine.html`。

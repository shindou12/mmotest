# 作業の分担: Opus（リーダー）と実装の担当（Sonnet のサブエージェント・Luna）

このリポジトリで、Claude Code（Opus）が、Claude Code のサブエージェント（Sonnet 5.5・Haiku 5.5）や Codex（GPT-6 Luna、`codex exec`）と分担して作業するときの規則です。**ここが正本**です。`CLAUDE.md` は要点とこの文書への案内だけ、`AGENTS.md`（Luna が自動で読む）は Luna 向けの守ることだけを書きます。食い違ったらこの文書に合わせて直します。

- 呼び出し: Sonnet のサブエージェント（Agent、`model: "sonnet"`、prompt に依頼の札）、または `sh tools/agents/luna.sh <依頼の札.md>`（ログインできたとき）。札の書式は `docs/agents/task-card.md`。準備は `sh tools/agents/setup.sh`。
- 手順の要約はスキル `.claude/skills/delegate`。
- 根拠（なぜこの分け方か）: ワールドマップの作業では、技術的な不具合の多く（シェーダーの使い回し F24、階調が効かない F25、仕上げの板が名前を消す、環境光 0 で黒くなる、色が文字列だった、JSON の Infinity が null）が**画面を見たときにしか見つからなかった**。描画に触れる作業は、画像と数値で確かめるまで終わりにしない。

## 1. 役割
| 役 | 担当 | しないこと |
|---|---|---|
| **Opus（リーダー）** | 方向づけ、作業の分解、依頼の札を書く、見た目の判断（見本との比較・規則の採用・構図・色・アセットの形）、描画の中心（シェーダー・光・階調を一から作る・直す）、レビュー、統合（コミット・プッシュ）、規則集と記録の更新、ユーザーへの報告 | 範囲の決まった実装を自分で長々と書くこと（回せるなら回す） |
| **実装の担当**: Sonnet 5.5 のサブエージェント（今の標準）、または Luna（`codex exec`、gpt-6-luna・推論強度 max。ChatGPT のログインができたとき） | 範囲と完了条件の決まった実装、道具づくり、移植、自動の確認の作成と実行、結果の報告 | 見た目の判断、規則集（`docs/world-art/rulebook.md`）の数値の変更、コミット・プッシュ、範囲外のファイルの変更 |
| **調べものの担当**: Haiku 5.5 のサブエージェント、検索用の Explore | ファイルや関数の洗い出し、長いログ・テスト出力の要約、文書の読み取り | 実装・判断 |
| **ユーザー** | 方針の決定、ログイン・課金・外部への公開の承認 | |

- **Luna が使えない間（ChatGPT のログインがない・コンテナが作り直された）は、Sonnet のサブエージェントが実装を担当する**。札と完了条件とレビューは同じ。
- **画像の生成（Luna の image_generation）**（ユーザー、2026-10-22）: 先に絵を作らせてから進めたほうが質や効率がよい作業では使う。**ただしアイコンはもう生成しない**（2026-10-22 夜、ユーザー: イメージと少し違う物が作られる）。アイコンは既存の 163 個（G7-1）か、ブラウザ版と同じ絵文字・記号を使う。札に「image_generation で作り、<パス> に保存」と書く。生成した絵は見本（規則を測る正本）にしない。ChatGPT のプランの利用枠で動く（API の従量課金ではない）
- **Luna の枠の見方と配分（2026-10-22 夜）**: `sh tools/agents/luna_limits.sh` で 5 時間の枠と 1 週間の枠の使った割合を見る（Plus プラン）。1 日で 1 週間の枠の 59% を使ったため、既定の速さを `default` に戻し（急ぐ札だけ `LUNA_TIER=fast`）、Luna は 1 本ずつ・空いた枠は Sonnet（比率はおよそ半々）。1 週間の枠が 85% を超えたら、戻るまで Luna は止めて Sonnet だけにする
- **Luna と Sonnet の分け方（2026-10-22 夜、ユーザーと決めた。本数でおよそ Luna 3 : Sonnet 1）**: Luna = 元のコードがあり照合や並べた画像で確かめられる移植（画面・モデル・式・書き出し）、数ファイルに収まる作業、急がない作業。Sonnet = 原因のわからない不具合の切り分け（例: 影の正体は札だった）、何本もの作業をまたぐ統合・手直し、照合の仕組みなど間違えると後に響く土台、Luna が止まった・上限のときの代わり。並行は「Luna 2 本 + Sonnet 1 本」くらいで、ChatGPT 側の上限と Claude 側の枠の両方を分散する
- **既定は Luna（推論 max・高速）**（ユーザー、2026-10-22）: 基本的な・簡単な実装、これまで Sonnet に渡していた種類の作業は、まず `sh tools/agents/luna.sh <札>`（既定で `model_reasoning_effort=max`・`service_tier=fast`）に渡す。報告と生の出力を見て、**任せてもだめそうだと判断したら Sonnet のサブエージェントに渡し直す**（だめと判断した理由を記録に残す）。
- サブエージェントを呼ぶときは**必ずモデルを指定する**（Agent の `model: "sonnet"` / `"haiku"`）。指定しないと Opus のまま動き、節約にならない。
- 担当の報告は要約と生の確認の出力だけを返させ、長いコードやログを会話に入れない。

## 2. 委任する作業の選び方
依頼する前に、作業を 3 つに分ける。迷ったら上の種類（より Opus 寄り）に入れる。

| 種類 | 例 | 誰が | 完了条件 |
|---|---|---|---|
| **A. 純粋な処理** | 式の移植（JavaScript → GDScript）、データの書き出し、道具・スクリプト、自動の確認、ドキュメントの機械的な更新 | Luna | 元の実装で作った入力と期待値の組と一致する。テストのコマンドの出力 |
| **B. 描画に触れる処理** | シェーダー・材質・階調・仕上げ・取り込み・地図の組み立ての拡張・Blender のアセットの作り方の変更 | 実装は Luna、判断は Opus | A に加えて、決まった視点で撮った画像（比較シート）と数値（`rulecheck.py`・`refstats.py`）。新しい仕組みは**値を 2 段変えて画素が変わる**ことを示す（rulebook 1.3） |
| **C. 見た目の判断** | 規則の採用、見本との比較、構図・色・アセットの形を決める、入／切の結論 | Opus | rulebook 1.2 の採用の条件 |

委任しない方がよいもの:
- 画像を見ながら値を何度も動かす微調整（往復が増えて節約にならない）
- 1〜2 回の小さな修正（依頼の札を書く方が高くつく）
- 原因のわからない見た目の不具合の調査（まず Opus が画像で切り分け、原因が決まってから直す作業を渡す）

## 3. 依頼の札（`docs/agents/task-card.md` の書式）
必ず書くこと: 目的 / 種類（A・B）/ 触ってよいファイル / 触ってはいけないもの / 守る約束（規則集や移植元の該当の節を名前で）/ 完了条件（コマンドと期待する出力）/ 返してほしいもの。
- 守る約束の例（描画）: 太陽の強さは three の強さ / π、半球光は材質の EMISSION、葉の法線は裏面で反転させない、仕上げは露出 → sRGB → 彩度 → ぼかしの順（`godot/worldart/README.md`）。
- 1 枚の札は 1 つの目的。大きな作業は Opus が分けてから渡す（目安: Luna の 1 回で、変更が数ファイル・数百行まで）。

## 4. レビューと検証（Opus）
1. Luna の報告（`last.md`）・変更の一覧（`git diff --stat`）・テストの出力を読む。**生の出力**で確かめる（「通りました」だけを信じない）。
2. 種類 B は、**差分より先に画像と数値**を見る。比較シートで前後を並べ、目標の範囲（rulebook 13.2）に入っているか。
3. 差分は要所だけ読む（触ってよい範囲を越えていないか、守る約束を破っていないか）。全部を読み直すのは、テストのない部分だけ。
4. Opus が自分で同じ確認を回す（`client_test.sh`、撮影）。通れば統合する。
5. 直しが要るときは、同じ作業の続き（`codex exec resume`）か、直す内容だけの新しい札で返す。2 回直しても通らない作業は Opus が引き取る。

## 5. ログと成果物
- 実行の記録は `.agents/runs/<日時>-<名前>/`（git に入れない）: `card.md`（依頼）、`last.md`（Luna の最後の報告）、`events.jsonl`（全経過）、`diffstat.txt`、`stderr.txt`。
- **Opus は `last.md` と `diffstat.txt` とテストの結果の行だけを読む**。`events.jsonl` は失敗の調査のときだけ、必要な所を grep する。長いログを会話に貼らない。
- Luna に、報告は短く（変えたファイル・確認のコマンドと結果の要約・未解決）書かせる。画像は保存した場所を書かせ、Opus が必要なものだけ開く。
- セッションは保存する（`--ephemeral` は使わない）。やり直しや続きに `codex exec resume` を使うため。使い捨ての問い合わせだけ `--ephemeral`。
- 秘密情報（API キー・トークン）をログ・札・報告・コミットに書かない。

## 6. サブエージェント・別モデルを使う条件
| 方法 | 使う | 使わない |
|---|---|---|
| **Claude のサブエージェント（Sonnet）** | 種類 A・B の実装の標準（Luna が使えない間）。依頼の札をそのまま prompt にする。触るファイルが他の作業と重ならないときは同じ作業ツリーで並行してよい。重なるときは `isolation: "worktree"` | 見た目の判断、描画の中心（シェーダー・光・階調の新しい仕組み） |
| **Claude のサブエージェント（Haiku・Explore）** | 重い読み取りと要約で、結論だけ欲しいとき（移植元の洗い出し、ログの要約、見本の分析） | 実装、見た目の最終判断（結論は Opus が画像と数値で確かめてから使う） |
| **`codex exec` 単独（Luna）** | ログインできたとき、種類 A・B の実装。Claude の利用枠を使わない | 見た目の判断。API キー（従量課金）での利用 |
| **Codex 内蔵のサブエージェント** | 使わない（中が見えず検証が増える。範囲を絞った依頼には不要） | |
| Claude のサブエージェントに `codex exec` を呼ばせる | 使わない（検証が 2 段になる） | |
| Workflow（多数のエージェントの一括） | ユーザーが明示したときだけ | 通常の作業 |

**入れない仕組みとその理由**: 実装の担当を 2 段に重ねる（サブエージェントの中でさらに委任する）、描画の撮影を担当に並行で回させる（ソフトウェア描画は CPU を食い合い、全部が遅くなる。撮影は同時に 1 つ）、担当どうしの自動のやり取り（統合と判断は Opus に集める方が速く安全）。

## 7. 作業の競合を避ける
- **生成物を書き換える作業は同時に 1 つだけ**: Blender の組み立て（`build_assets.py`・`build_map.py`）、Godot への書き出し（`export_godot.py`・`export_gamedata.mjs`・`export_models.mjs`）、撮影の `art/shots/` への書き込み、`art/blender/*.blend`。`build_assets.py --only` は assets.blend を一部だけで上書きするので、本番の場所には使わない（`--out`・`--blend` で別の場所へ）。
- **並行する担当の作業は、触るファイルが重なるなら worktree を分ける**（`luna.sh --worktree`、サブエージェントは `isolation: "worktree"`）。重ならない新しいファイルだけなら同じ作業ツリーでよい。同じファイルを触る札を同時に出さない。
- **撮影（ソフトウェア描画）は同時に 1 つだけ**。CPU を食い合い、全部が遅くなる。触ってよいファイルが重ならないことを、札を出す前に Opus が確かめる。
- Luna は**コミット・プッシュしない**。統合（コミット・プッシュ・ブランチの操作）は Opus だけがする。
- 規則集・記録（`docs/world-art/rulebook.md`・`goal-*.md`・`pipeline.md` の失敗集）は Opus が直す。Luna は失敗と原因を報告に書き、Opus が反映する。
- three.js（`public/worldart/world.js`）と Godot（`godot/worldart/shaders/`）は同じ式で保つ。片方を変える札には、もう片方を変えるか、変えない理由を書く。

## 8. 費用（従量課金をしない）
- **従量課金が発生する利用は、ユーザーの明示的な承認なしに行わない**。OpenAI API キーでの Codex の利用（標準の API の料金で課金される）はこれに当たるので、API キーの登録・要求・使用をしない。
- Luna は **ChatGPT のアカウントでのログイン**（プランに含まれる利用枠）だけで使う。利用枠を使い切ったときに追加のクレジットを買う・課金の設定や支払い方法を変える、はしない（ユーザーが判断する）。
- 認証は `codex login --device-auth`（端末に出るリンクと一回限りのコードを、ユーザーがブラウザで承認する）。ログインの情報は Codex がこのコンテナの `~/.codex/auth.json` に持ち、コンテナが作り直されると消える（そのたびにログインし直す）。中身を表示・コピー・コミットしない。

## 9. ユーザーに相談する条件
次のときは作業を止めて相談する（Opus が判断し、Luna は Opus に返す）。
- ログイン・課金・権限・承認が要る（秘密情報を会話に貼ってもらわない。従量課金は 8 のとおり行わない）
- 外部に公開・送信する（プル要求、Artifact の公開範囲を広げる、他のサービスへの送信）。ユーザーの依頼にすでに含まれていれば不要
- 履歴の書き換え・強制プッシュ・大量削除など、戻しにくい操作
- 方針・規則・優先度を変える判断（例: 規則集の数値の目標を変える、正本を three.js から Godot に移す）
- 見本と規則が食い違い、どちらを優先するか決められない
- 依頼の範囲が大きく広がる、または見積もりの倍以上かかりそう

## 10. Opus のトークンを節約する習慣
- 会話を長くしすぎない。区切り（チェックポイント）ごとに引き継ぎを文書に残し、新しい会話で続ける。
- 委任の効果は移植・道具づくりで大きく（Opus の 5〜8 割減）、見た目の判断が中心の時期は小さい（1〜2 割減）。描画の微調整を渡して往復を増やさない。
- 確認の道具ごと渡し、結果の要約と生の出力の要所だけ受け取る。
- **Blender MCP（2026-10-22 の方針、未導入）**: ゼロから新しいアセットを作るときの形の試作に使う候補（Blender の画面を見ながら試す）。決まった形は必ず `tools/worldart/blender/build_assets.py` のスクリプトに書き起こす（作り直せることを守る）。入れるときは公開元と版を確かめ、決まったコミットから、Blender 4.2.23 で使う
